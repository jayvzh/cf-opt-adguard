# AlbumShelf・NAS图集馆 产品需求文档（PRD）

> 版本：v1.0 ｜ 状态：已定稿 ｜ 面向：AI IDE 开发 + 人类评审

---

## 1. 项目定位

**AlbumShelf・NAS图集馆** 是一个面向 NAS / 私有服务器部署的**轻量级、自托管、高性能 Web 图片浏览器**，专注于：

- 文件夹浏览
- 图片大图浏览（Zoom / Pan / Fit / Fullscreen）
- 底部缩略图 Filmstrip 导航
- 高级文件排序（自然排序 / Regex 排序 / 多规则排序）
- 双页阅读模式（Spread：竖图自动拼双页、横图自动单页满幅，参考 NeeView 見開き逻辑）
- Docker / NAS 一键部署

一句话：**不是照片管理系统，而是专业的 Web Image Viewer。**

## 2. 项目背景

### 2.1 问题 1：现有工具的图片浏览体验不足

常见 Web 文件管理器（如 Zdir）核心是文件索引/分享/WebDAV，图片预览只是附属功能，缺少：

- 底部缩略图 Filmstrip（当前图自动居中、快速点击切换、键盘/滚轮导航）

### 2.2 问题 2：文件排序混乱

- 字典序导致 `1.jpg, 10.jpg, 100.jpg, 11.jpg, 2.jpg, 20.jpg`
- 复杂文件名如 `chapter1_page1.jpg` / `chapter10_page1.jpg` 需要自然排序、Regex 提取数字排序、多规则组合排序

### 2.3 问题 3：缺少双页连续阅读体验

漫画、扫描件、连续图片的阅读需要像翻书一样的双页拼凑（NeeView 見開き模式）：

```
┌──────────┬──────────┐     ┌─────────────────────┐
│          │          │     │                     │
│   页 A   │   页 B   │     │      横图 C         │
│          │          │     │                     │
└──────────┴──────────┘     └─────────────────────┘
  两张竖图自动拼成双页          横宽图自动独占整屏
```

核心诉求：**切换双页模式后自动布局拼凑**——只对足够窄的竖图两两拼页，较宽的横图保持单页满幅，翻页节奏不被打断。这是为了提升浏览体验，而不是图片对比工具。

## 3. 产品目标

### 3.1 核心目标

构建一个轻量级、自托管、高性能的 Web 图片浏览器，MVP 功能清单：

1. 文件夹浏览
2. 图片列表
3. 大图浏览
4. 底部缩略图 Filmstrip
5. 上一张 / 下一张
6. 自然排序
7. Regex 排序
8. 双页阅读模式（Spread 自动拼页）
9. Docker 部署

### 3.2 非目标（第一阶段明确不做）

- AI 人脸识别 / AI 图片识别 / 相册自动分类
- 地图、时间线、社交、用户社区
- 在线图片编辑
- 复杂 DAM（数字资产管理）

**避免做成 PhotoPrism / LibrePhotos / Immich 那种大型照片管理系统。**

## 4. 用户场景

### 场景 A：浏览 NAS 图片

用户打开 Web → 左侧目录树选择 `/photos/Comics` → 进入浏览。支持目录：

```
/photos/
├── Anime
├── AI
├── Comics
└── Wallpapers
```

### 场景 B：连续浏览图片

打开 `chapter01/`（001.jpg ... 100.jpg），大图区显示当前图，底部 Filmstrip 显示附近缩略图：

```
┌─────────────────────────────┐
│            050              │
├─────────────────────────────┤
│ [48][49][50][51][52][53]    │
└─────────────────────────────┘
```

操作：`←` 上一张、`→` 下一张、`Space` 下一张、点击缩略图直达。

### 场景 C：自然排序

`page_1.jpg, page_2.jpg, page_10.jpg, page_20.jpg` → 选择 Natural Sort → `1, 2, 10, 20`。

### 场景 D：Regex 排序

`Chapter1_Page1.jpg ... Chapter10_Page1.jpg`，用户设置 Regex `Chapter(\d+)_Page(\d+)`，按 Group 1（数字升序）→ Group 2（数字升序）排序，得到正确的章节-页码顺序。

### 场景 E：双页连续阅读

用户打开漫画目录，切换到双页模式（Spread），界面自动拼页：

```
┌──────────┬──────────┐     ┌─────────────────────┐
│          │          │     │                     │
│  001.jpg │  002.jpg │     │      003.jpg        │
│  (竖图)  │  (竖图)  │     │      (横图)         │
│          │          │     │                     │
└──────────┴──────────┘     └─────────────────────┘
   两张竖图拼成双页            横图自动独占一屏
```

- 竖图两两拼成左右双页，像翻开的书
- 横图（宽图）自动独占整屏，不打乱后续配对节奏
- 按 `→`：单页帧与双页帧按实际布局顺序混合翻页
- 阅读方向可选（日漫右开本 / 普通左开本），与 NeeView 見開き体验一致

## 5. 功能需求

> 编号规则：F0xx。每个 Sprint 只实现对应功能，禁止提前实现。

### F001 文件夹浏览

- 浏览根目录、子目录、图片文件（只读，不提供上传/删除/重命名）
- 服务端通过 `IMAGE_ROOT` 配置允许浏览的根目录，做路径安全校验
- MVP 支持格式：`jpg / jpeg / png / webp / gif`
- Phase 2：`avif / heic / tiff`；未来：RAW（`cr2 / nef / arw`）

### F002 图片浏览

- **默认加载预览图（Preview，长边约 1920px）**——原图可能十几 MB，不适合直接网页浏览
- **加载原图**：用户主动点击"加载原图"后切换为原图显示（**不自动显示原图**，每次进入均默认预览图）；原图 URL 带版本参数 + immutable 缓存头，**同一张图再次点击"加载原图"时直接命中浏览器缓存，无需重新下载**
- Zoom、Pan、Fit、Actual Size（100%）、Fullscreen、旋转
- 快捷键：`←` 上一张、`→` 下一张、`Space` 下一张、`F` 全屏、`0` Fit、`1` 100%

### F003 Filmstrip（底部缩略图条）

- 底部水平滚动缩略图条，`[001][002][003]...`
- 横向滚动 + 虚拟渲染（Virtual Render，大目录不一次性渲染全部节点）
- 缩略图等高不等宽（宽度按原始宽高比缩放）；**可见数量根据视口宽度、缩略图宽度与间距动态计算，不硬编码固定数量**，窗口缩放自动适配
- 当前图片缩略图高亮并自动居中
- 缩略图 Lazy Load（懒加载）

### F004 基础图片排序

- Filename（A→Z / Z→A）
- Natural（1, 2, 10, 20）
- Modified Time（旧→新）
- Created Time（旧→新）
- File Size（小→大）

### F005 Regex 排序

- 用户输入 Regex（如 `chapter(\d+)_page(\d+)`）
- 配置 Capture Group、Numeric（按数字还是字符串比较）、Direction（ASC/DESC）
- 未匹配文件策略：MVP 固定"排在已匹配文件之后"；未来支持 First / Last / Ignore

### F006 多规则排序

多条规则依序生效（Rule 1 → Rule 2 → ...），例如：

- Rule 1：`chapter(\d+)`，Group 1，Numeric，ASC
- Rule 2：`page(\d+)`，Group 1，Numeric，ASC

规则以 JSON 配置描述，可保存到文件夹设置中。

### F007 双页阅读模式（Spread）

> 定位：双页拼凑是为了**连续阅读体验**（漫画 / 扫描件 / 连续图片），不是图片对比工具。详细算法见 docs/SPREAD_ENGINE.md。

- 布局模式：Single（单页）/ Spread（双页自动拼凑）
- **自动拼凑规则**（参考 NeeView PageFrameFactory）：
  - 横图判定：`width > height × WideRatio`（WideRatio 默认 1.0，可配置）
  - 横图 → 独占一帧，满幅显示
  - 竖图 → 与相邻竖图两两拼成双页（等高对齐缩放）
  - 无可配对竖图（下一页是横图 / 末尾）→ 本页独占一帧，可选插入空白页（Dummy Page）补位
  - 封面 / 封底可配置单页显示
- 阅读方向：LeftToRight / RightToLeft（日漫右开本）
- 可选：静态配对模式（按页码奇偶固定配对，不因横图打乱分组）
- 双页显示：等高缩放、垂直居中、页间距可配置
- 翻页按"帧"推进：单页帧与双页帧混合顺序，`←`/`→`/`Space` 一次翻一帧
- Filmstrip 联动：当前帧包含的图片缩略图同时高亮

### F008 图片信息

显示 Filename、Resolution（宽×高）、File Size、Modified Time。Phase 2 可扩展 EXIF。

### F009 文件夹设置（每目录记忆）

每个文件夹可保存：Sort Mode、Regex Rule（含规则 JSON）、View Mode、阅读设置（PageMode / ReadOrder / WideRatio / 封面封底单页等）。例如：

- `/Comics` → Regex Sort + 双页模式 + 右开本
- `/Photos` → Date Sort + 单页模式
- `/AI` → Natural

### F010 收藏 / 标签（收藏 Sprint 9 已实现，标签 Phase 2）

**收藏**（Sprint 9 提前实现）：心形收藏/取消收藏——查看器 ✕ 下方浮动按钮组（双页帧竖排 L/R 两个）、网格卡片右上角角标、S 键快捷键（双页收藏左图）；入口为侧栏虚拟「收藏夹」（收藏时间倒序）与目录内「只看收藏」筛选；收藏夹视图强制单页帧化；纳入配置导入导出（合并语义，version 保持 1）；auth enabled 时游客完全隐藏。数据模型见 DATA_MODEL.md §2.3，API 见 API.md §3.14。

**Rating、Tags**：Phase 2 实现（数据表 tags / image_tags 已预留，见 DATA_MODEL.md §2.4）。

## 6. 阶段划分

| 阶段 | 内容 |
| --- | --- |
| MVP（Sprint 0-7） | 文件夹浏览（含图片尺寸读取）、图片浏览（默认预览图 + 按需原图）、Filmstrip、缩略图/预览图双端缓存（服务器持久 + 浏览器 immutable）、基础排序、Regex/多规则排序、双页 Spread 自动拼页、Docker 部署 |
| Phase 2 | 静态配对模式、Dummy Page 补位、单页横图拆屏（DividePage）、Rating、Tags、EXIF、avif/heic/tiff（收藏已提前至 Sprint 9） |
| 远期 | RAW 支持、全景连续滚动（Panorama）、WebDAV/S3 存储层、多用户 |

> 备注：本产品**不做**图片对比工具（A/B 对比、Wipe 拉帘、像素 Difference）；双页模式是阅读体验功能。

## 7. 成功标准

1. `docker compose up` 后浏览器访问即可完整完成场景 A-E
2. 10000+ 图片目录下 Filmstrip 流畅滚动（虚拟渲染生效）
3. 预览图首屏加载 ≤ 300ms（局域网、服务器缓存命中）；缩略图/预览图重访同目录命中浏览器缓存（0 网络请求）；同一张原图重复点击"加载原图"命中浏览器缓存（无重新下载）
4. 所有路径类 API 通过路径安全校验（越界访问返回 `INVALID_PATH`）
